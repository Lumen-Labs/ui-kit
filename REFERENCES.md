# Design References

Lumen is an original synthesis rather than a code fork. The package uses its own component API, markup, styles, and tokens while drawing on the following official design-system guidance.

## Sources and applied principles

- [Atlassian Design System](https://atlassian.design/) — semantic tokens and layout primitives; its [component catalog](https://atlassian.design/components), [dynamic table](https://atlassian.design/components/dynamic-table), [layout](https://atlassian.design/components/navigation-system/layout), [grid](https://atlassian.design/foundations/grid-beta/applying-grid/), [inline edit](https://atlassian.design/components/inline-edit), [typography guidance](https://atlassian.design/foundations/typography/applying-typography), [radius guidance](https://atlassian.design/foundations/radius/), and [iconography foundation](https://atlassian.design/foundations/iconography/) informed composable primitives, semantic type, restrained radius tiers, page structure, focused editing, familiar metaphors, and controlled pagination and sorting.
- [Carbon Design System](https://carbondesignsystem.com/) — contextual color and layered surfaces; its [component overview](https://carbondesignsystem.com/components/overview/components/), [data-table usage](https://carbondesignsystem.com/components/data-table/usage/), [data-table accessibility](https://carbondesignsystem.com/components/data-table/accessibility/), [global header pattern](https://carbondesignsystem.com/patterns/global-header/), [modal accessibility guidance](https://carbondesignsystem.com/components/modal/accessibility/), [icon usage](https://carbondesignsystem.com/elements/icons/usage/), and [React icon code guidance](https://carbondesignsystem.com/elements/icons/code/) informed table toolbars, batch actions, sortable columns, pagination placement, constrained keyboard focus, shell selection, code-copy actions, and the optional icon entrypoint.
- [Elastic UI](https://eui.elastic.co/) — restrained action hierarchy and component-scoped tokens; its [data grid](https://eui.elastic.co/docs/components/tabular-content/data-grid/), [data-grid toolbar](https://eui.elastic.co/docs/components/data-grid/toolbar/), [search and filter bar](https://eui.elastic.co/docs/components/forms/search-and-filter/search-bar/), [page template](https://eui.elastic.co/docs/components/templates/page-template/), [button guidance](https://eui.elastic.co/docs/components/navigation/buttons/guidelines/), and [modal guidance](https://eui.elastic.co/docs/containers/modal/) informed predictable toolbar control placement, field-value facets, the table-versus-grid boundary, content width, one clear primary action, and focused dialogs.
- [GitLab Pajamas](https://design.gitlab.com/) — content-first actions, explicit link-versus-button semantics, visible focus, and accessible dialog labeling; its [table](https://design.gitlab.com/components/table/), [layout foundation](https://design.gitlab.com/product-foundations/layout/), [navigation sidebar pattern](https://design.gitlab.com/patterns/navigation-sidebar/), [component collection](https://design.gitlab.com/components/), and [attribute list](https://design.gitlab.com/components/attribute-list/) informed visible row actions, responsive overflow decisions, captions, shell behavior, avatar grouping, summary rows, and truncation.
- [PatternFly](https://www.patternfly.org/) — product-oriented React composition and explicit modal focus restoration/background blocking; its current [toolbar](https://www.patternfly.org/components/toolbar/) and archived [toolbar design guidance](https://v4-archive.patternfly.org/v4/components/toolbar/design-guidelines/), [table](https://www.patternfly.org/components/table/), [data list](https://www.patternfly.org/components/data-list/), [page guidelines](https://www.patternfly.org/components/page/design-guidelines/), [page accessibility](https://www.patternfly.org/components/page/accessibility/), and [iconography foundation](https://www.patternfly.org/foundations-and-styles/iconography/) informed composable and responsive toolbar groups, flexible action lists, declarative native-table structure, page sections, unique navigation labels, and semantic icon tones.
- [GOV.UK Design System](https://design-system.service.gov.uk/) — plain-language, task-specific action labels and sparse primary actions; its [layout guidance](https://design-system.service.gov.uk/styles/layout/), [service navigation](https://design-system.service.gov.uk/components/service-navigation/), [component catalog](https://design-system.service.gov.uk/components/), [task list](https://design-system.service.gov.uk/components/task-list/), and [error message guidance](https://design-system.service.gov.uk/components/error-message/) informed mobile-first content widths, page wrappers, date segments, password visibility, error summaries, summary lists, and task status wording.
- [U.S. Web Design System](https://designsystem.digital.gov/) — standard HTML controls, visible focus, explicit input labels, and context-level accessibility testing; its [table](https://designsystem.digital.gov/components/table/), [collection](https://designsystem.digital.gov/components/collection/), [header](https://designsystem.digital.gov/components/header/), [side navigation](https://designsystem.digital.gov/components/side-navigation/), [layout grid](https://designsystem.digital.gov/utilities/layout-grid/), and [icon guidance](https://designsystem.digital.gov/components/icon/) informed focusable overflow regions, sort announcements, semantic resource lists with metadata, clear navigation labels, mobile-first grids, and progressive enhancement.
- [Design Tokens Community Group](https://www.designtokens.org/) — interoperable, platform-agnostic design decisions. `src/tokens/core.tokens.json` targets the stable [Format Module 2025.10](https://www.designtokens.org/tr/2025.10/format/).
- [Firecrawl](https://www.firecrawl.dev/) — visual research into continuous full-width section rhythm, shared grid lines, compact numbered framing, functional status/data motion, and dense specimen presentation informed Lumen's original contiguous-section patterns and connected icon-catalog showcase. No Firecrawl code, brand assets, or proprietary visual elements are included.
- [Neo4j Browser styling](https://neo4j.com/docs/browser/operations/browser-styling/) — its visible node-label and relationship-type styling model informed Lumen's labeled categorical rings and relationship captions.
- [Neo4j Bloom search](https://neo4j.com/docs/bloom-user-guide/current/bloom-visual-tour/search-bar/) — its search-first graph exploration informed the placement of Lumen's search and graph vocabulary facets. Lumen does not implement Bloom search phrases, Cypher, or database-backed full-text search.
- [Neo4j Explore](https://neo4j.com/docs/desktop/current/explore/) — its search, vertical tools, minimap, and legend model informed the placement and progressive disclosure of Lumen's original graph workbench controls.
- [Neo4j NVL overview](https://neo4j.com/docs/nvl/current/) and [NVL license](https://neo4j.com/docs/reference/license/nvl/) — architectural research into Neo4j's GPU graph viewer and the published restriction that prevents Lumen from using NVL outside Neo4j products.
- [vis-network](https://visjs.github.io/vis-network/docs/network/) — its retained Canvas2D network, ForceAtlas2-based physics, stabilization events, dragging, selection, and camera APIs power Lumen's interactive graph canvas.
- [Graphology ForceAtlas2](https://graphology.github.io/standard-library/layout-forceatlas2.html), [Noverlap](https://graphology.github.io/standard-library/layout-noverlap.html), and [Louvain](https://graphology.github.io/standard-library/communities-louvain.html) — pure layout helpers and topology-aware community guidance behind Lumen's hierarchy and semantic zoom behavior.

## Framework references

- [Tailwind CSS source detection](https://tailwindcss.com/docs/detecting-classes-in-source-files) documents `@source` for component libraries ignored by normal dependency scanning.
- [Tailwind CSS theme variables](https://tailwindcss.com/docs/theme) documents shareable `@theme` variables and npm-distributed theme packages.
- [Next.js CSS](https://nextjs.org/docs/app/getting-started/css) recommends global Tailwind setup in the root stylesheet and supports external package stylesheets.
- The installed Next.js documentation in the consuming project remains authoritative for Server/Client Component boundaries and version-specific APIs.

## Actions implementation references

The current Button and Toolbar contracts synthesize the official [Atlassian Button](https://atlassian.design/components/button) and [Button group](https://atlassian.design/components/button/button-group), [Carbon Button](https://carbondesignsystem.com/components/button/usage/), [Elastic UI Button](https://eui.elastic.co/next/docs/components/navigation/buttons/button/), [GitLab Pajamas Button](https://design.gitlab.com/components/button/) and [Button group](https://design.gitlab.com/components/button-group/), [PatternFly Button](https://www.patternfly.org/components/button/design-guidelines/) and [Toolbar](https://www.patternfly.org/components/toolbar/), [GOV.UK Button](https://design-system.service.gov.uk/components/button/), and [USWDS Button](https://designsystem.digital.gov/components/button/) and [Button group](https://designsystem.digital.gov/components/button-group/) guidance. The toolbar focus model follows the [WAI-ARIA Authoring Practices Toolbar Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/). Lumen retains its own tokens, visual language, component API, and source code.

## Forms implementation references

The current field and choice-control anatomy synthesizes the official [Carbon text input](https://carbondesignsystem.com/components/text-input/usage/), [form](https://carbondesignsystem.com/components/form/usage/), [dropdown](https://carbondesignsystem.com/components/dropdown/usage/), [radio](https://carbondesignsystem.com/components/radio-button/usage/), and [number input](https://carbondesignsystem.com/components/number-input/usage/) guidance; [PatternFly form](https://www.patternfly.org/components/forms/form/design-guidelines/) and [switch](https://www.patternfly.org/components/switch/design-guidelines/) guidance; [GitLab checkbox](https://design.gitlab.com/components/checkbox/) guidance; and [USWDS radio](https://designsystem.digital.gov/components/radio-buttons/) guidance. Lumen keeps native HTML controls, its own semantic tokens, original 6px control radius, shared 44px field shell, and existing raised/pressed button treatment.

## Attribution boundary

Do not copy implementation code or protected visual assets from these systems into Lumen without verifying their licenses. Preserve links and paraphrase behavioral guidance. Accessibility claims apply only after the components are tested in the consuming application's real content and interaction context.

The icon adapter imports the separately installed `@carbon/icons-react` package, whose [upstream repository](https://github.com/carbon-design-system/carbon) is published under Apache-2.0. Lumen does not copy its SVG assets or vendor brand marks; consumers remain responsible for the peer package's license and notices.
